- 요청된 수정은 구현부터 기존 방식의 main 반영 및 카페24 배포까지 마무리한다. 이미 허용된 배포를 매번 재확인하지 않는다.
- 로컬 런타임 테스트를 돌리지 말고 실제 카페24에서 확인하는 방식을 선호한다. 정적 구문 확인과 `git diff --check`는 사용 가능. 배포 스크립트의 격리 검증은 유지한다.
- 운영 자료, 기존 계정/비밀번호, 지급·게시 급여, 변경 이력은 보존한다. 테스트 샘플 변경은 명시적인 테스트 자료에 한정한다.
- 변경 후 배포 완료를 말하기 전에 실제 새 자산과 관련 API/화면을 확인한다. 서버 로그를 직접 읽지 못했으면 읽었다고 말하지 않는다.
- 한국어로 짧고 명확하게 진행 상황을 알린다. 작업 중 60초 이상 설명 없이 두지 않는다.
- 디자인은 깔끔한 회사 업무시스템 느낌, 가능한 한 한 줄, 펼침 목록 활용, 불필요한 스크롤을 줄이는 방향. 마우스 오버 효과도 유지한다.
- 새 서브에이전트는 사용자 또는 적용되는 지침이 명시적으로 요청한 경우에만 추가한다.

## 가장 최근 변경: 팀별 그레이드

- 기존 그레이드, 보험 전용 자동 계산 및 비교표는 **보험팀** 기준이다.
- 관리자 그레이드 화면에서 **보험팀 / 화장품팀 / 건강보조식품팀**을 각각 선택해 일·주·월 기준과 적용일을 따로 저장한다.
- 화장품·건강보조식품에는 보험의 7건 누적 기준, 8건 주 기준, 보험 월 비교표, 자동 주 구간을 상속하지 않는다. 해당 팀은 빈 금액과 일반 구간 편집으로 시작한다.
- 다른 팀의 과거 보험 복사 자료는 DB에 그대로 보존하되, 그 팀의 전용 기준으로 적용하거나 공개하지 않는다.
- 새 저장의 정책에 `departmentScope`, `departmentScopeVersion: 1`을 기록한다. 보험 외 팀은 이 표식이 자기 팀과 맞는 자료만 사용한다.
- 전용 기준이 유효한 적용일에 도달하기 전에는 해당 직원의 그레이드 메뉴·홈 패널·상단 일/주/월 칩을 숨긴다. 직접 그레이드 페이지 접근과 관련 직원 계산 API도 제한한다. 보험 직원은 기존 표시를 유지한다.
- 직원 조회는 인증된 직원의 팀으로 고정한다. 클라이언트가 보낸 다른 팀 값을 신뢰하지 않는다.
- 일·주·월 부분 저장, 미래 적용 예약, 기존 이력·revision 충돌 검사는 유지한다.
- 핵심 파일: `server/lib/grade-departments.php`, `grade-settings.php`, `grade-ledger.php`, `bootstrap.php`, `grade-summary.php`, `grade-estimates.php`, `daily-grade.php`, `policy.php`, `native.php`, `server/public/office.php`, `grade-estimates.php`, `grade-personal-totals.php`, `server/views/office.php`, `partials/sidebar.php`, `office.js`, `grade-header.js`.
- `server/bin/check-grade-departments.php`를 배포 검증에 추가했다. 격리 SQLite에서 팀 간 저장 격리, 기존 자료 보존, 미래 공개일, 보험 전용 계산 제외를 검사한다.
- 실제 확인: 새 `office.js`와 `grade-header.js` 해시 일치, 보험 테스트 직원 로그인 성공, `gradeAvailable: true`, 부트 데이터에 보험 이력만 포함, `grade-summary-api.php` 정상 응답. 화장품/건강보조식품 직원의 실제 로그인은 확인하지 않았다. 관리자 계정 정보는 이 대화에서 확보하지 않았다.

## 완료되어 유지해야 할 최근 기능

### 가접수·재접수

- 직원 **접수 가능지역** 바로 아래 본인의 가접수 표가 있다. 관리자 접수관리에도 표시한다.
- **전체 가접수 / 오늘 재접수 가능 / 관리자 확인 대기** 카드가 각각 해당 목록을 펼친다. 같은 카드 재클릭은 닫고 기본 상태는 닫힘이다. 직원 목록은 페이지당 10건이다.
- 전체 가접수는 전체 수량, 오늘 가능은 오늘 정책에 해당하는 수량만 표시한다. 정책 우선·오래된 순 정렬 및 펼침 상세를 유지한다.
- 상세 접수 내용 수정, 이어 쓰는 메모, 작성 날짜·시·분, 재콜/수정 후 관리자 정상접수 확인 흐름을 유지한다. 불필요한 ‘확인 필요’ 아이콘은 제거했다.
- 테스트 카드 샘플은 user1 전용 추가 5건: 오늘 가능 3건, 관리자 대기 2건. 기존 42건은 보존하여 당시 전체 47건이었다. 테스트 전용 정책은 해당 기록에만 연결하며 실제 공통 정책을 바꾸지 않는다.
- 샘플의 가능 정책 날짜는 **2026-10-01 한국 시간**이다. 다음 날짜에는 오늘 가능 수량이 자연스럽게 달라진다. 숫자를 고정하거나 운영 정책을 변경하여 맞추지 않는다. 시드 배치는 중복 실행에 안전하다.

### 출근·세션·화면

- 직원 홈 출근 버튼은 오전 10시 전 출근도 인정시간 10:00으로 기록한다. 직원은 상태만 보고 관리자는 시각을 본다. 중복 출근 기록은 변경하지 않는다.
- 열린 페이지는 60초 주기로 세션을 유지한다. 관리자는 인사·출결에서 세션 유지시간을 5~1440분 범위로 설정한다.
- 홈의 실적관리 수량, 마지막 확인, 출근은 가능한 한 한 줄로 정리했다. 출결의 테스트 직원 패널과 직원 인사기록은 기본 닫힌 펼침 목록이다.
- 인사·출결의 직원 목록, 직원 등록, 근로계약서는 모두 버튼 형태다.
- 직원·관리자 달력은 전달/다음달 날짜로 모든 주의 빈칸을 채운다. 실적 달력의 A/S 0건은 빈 표시다. 영업일 달력의 이웃 달 날짜는 저장 대상 체크박스로 만들지 않는다.

### 직원 등록 요청과 승인

- 로그인 하단 **직원 등록 요청** → `/signup.php`.
- 가입 요청 계정은 비활성/승인 대기로 생성한다. 관리자 **인사·출결 → 직원 등록 승인** 및 근로계약서 목록에서 승인할 수 있다.
- 승인 시 팀·입사일을 지정하고 계정 활성화 및 HR 직원 연결을 트랜잭션으로 처리한다. 거절 계정은 로그인할 수 없다.
- 승인 후 직원 첫 로그인은 `/profile-entry.php`에서 본인 정보를 입력한다. 허용된 개인 정보만 수정 가능하고 팀·권한·급여·계약일 등은 직원이 바꿀 수 없다.
- 관리자 상단 팝업은 대기 수량을 알리고 15초마다 확인한다. 새로운 대기 요청이 생기면 다시 알린다.
- **직원 등록 요청 비밀번호에는 길이 제한을 요구하지 않는다.** 비어 있지 않은지만 확인한다. `cnc-sha256:` 저장 방식으로 긴 비밀번호의 bcrypt 잘림을 피하고 기존 해시 로그인도 지원한다.
- 관리자 수동 직원 등록의 기존 비밀번호 규칙과 혼동하지 않는다. 관련 파일은 `memberships.php`, `membership-notification.php`, `profile-entry.php`, `server/lib/membership.php`, `passwords.php`, `membership-notification.js`, `membership.css` 및 `check-membership.php`.

### 공지·로그인 팝업

- 회사 공지와 정책 수량 감소 헤더를 공통 PHP 직원/관리자 페이지와 접수 팝업에 넣었다. 실제 공지 목록 링크와 관리자 관리 버튼을 유지한다.
- 수량 감소 알림은 5초 깜박인 뒤 고정한다. 회사 공지는 별도 표시 및 목록 연결을 유지한다.
- 로그인 때 이미지 공지가 뜬다. 내용: “현재 시스템은 정식배포용이 아니며 개발안정화를 거치지 않은 것임으로 시급계산 혹은 그레이드 연산 등의 민감한 정보는 관리직원과 반드시 상의하시기 바랍니다.”
- **오늘은 열지 않기**는 계정·역할·공지 버전·한국 날짜별로 저장한다. X/확인/Escape로 닫을 때 반영하며 다음 날 다시 표시한다.
- 파일: `login-notice.js`, `login-notice.css`, `login-system-notice-v1.png`, `server/views/partials/login-notice.php` 및 공통 native 헤더. 계약서 출력물에는 앱 헤더를 인쇄하지 않는다.

### 보험 급여와 샘플

- 샘플은 22일 만근 기준. 시간근무 수당은 그레이드별 시급에 따라 달라야 하며 관리자/직원 계산은 동일한 PHP 원장을 사용한다.
- 사용자 요청으로 표시 괄호는 `22일 × 시급` 형태다. 실제 총액은 기존 인정시간 계산을 사용하므로 표시 문구만 보고 일당 계산으로 바꾸지 않는다. 예: 132시간 × 15,000원 = 1,980,000원, 표시에는 22일을 사용한다.
- 보험 일그레이드는 7건 기준 누적, 주그레이드는 8건 기준을 적용하되, 월 기준표 **90건 이하 / 91~100건** 행의 일·주·월 그레이드는 사용자 요청으로 0원이다. 임의로 최하 지급액으로 되돌리지 않는다.
- 실제 이력, 게시·확정된 급여, 일 선지급 공제를 유지한다. 선지급을 두 번 차감하지 않는다.
- 세부 공식은 현재 `grade-ledger.php`, `grade-estimates.php`, 관련 격리 검사 및 `docs` 문서를 확인한다. 일부 오래된 README 설명은 현재 기능과 다르므로 코드·최신 요청을 우선한다.

## 이어서 작업하는 방법

1. 최신 main과 작업 트리를 확인하고, 요청에 해당하는 소스를 읽는다. 기존 사용자 변경을 덮어쓰지 않는다.
2. 요청 범위의 수정과 필요한 정적 검사를 완료한다. 로컬 런타임 테스트 실행은 사용자 선호를 따른다.
3. 이 환경에서는 GitHub CLI 읽기/fetch는 가능했으나 `git push`에 인증 정보가 없어 실패했다. GitHub connector의 `create_tree` → `create_commit` → `update_ref(force:false)`로 main을 갱신했다. 직접 push가 가능한 새 환경이라면 그 방법도 사용할 수 있다.
4. 새 커밋의 부모는 항상 현재 remote main으로 확인한다. 비강제 업데이트로 경쟁 변경을 보호한다. 큰 `office.js`는 1MB 이상이며 `create_blob` 후 tree에 SHA를 넣는 편이 안정적이었다. 본문이나 자산 전체를 도구 출력에 쏟지 않는다.
5. 서버 직접 SSH는 이번 환경에서 연결되지 않았다. 반복해서 막힌 SSH를 시도하거나 사용자에게 같은 연결을 다시 요구하지 않는다. 우선 기존 자동 배포를 사용한다.
6. `server/deploy.sh`가 PHP lint, 격리 검사, 백업, 보존형 마이그레이션, 중복 방지 테스트 시드, 파일 배포 및 PHP 실행 확인을 수행한다. 자동 배포 실패 커밋은 동일 커밋으로 계속 재시도하지 않는다. 수정 커밋 또는 실제 서버 로그 확인이 필요하다.
7. 라이브 자산 해시와 해당 기능의 HTTP/API 응답을 확인한 뒤 완료를 보고한다. 테스트 계정은 user1이며 비밀번호는 이 문서에 보관하지 않는다. 관리자 계정을 추측하지 않는다.
