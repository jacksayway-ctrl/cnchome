# TM OFFICE 자체 운영 구성

## 운영 원칙
- 실행 중 외부 API, CDN, 외부 지도 SDK, 외부 인증·분석 서비스에 의존하지 않는다.
- 화면·지도·아이콘·폰트·라이브러리는 회사가 보유한 파일로 제공한다.
- GitHub Pages는 합성 예시 데이터 미리보기 배포용이다. 실제 고객·직원·급여 데이터는 올리지 않는다.
- 자체 운영은 회사가 서비스와 데이터를 직접 관리한다는 뜻이다. 모든 직원 PC가 각자 독립된 데이터를 갖는 방식은 아니다.
- 외부에서 근무하려면 회사 내부 서버에 안전하게 접근할 경로가 별도로 필요하다. 완전 오프라인에서는 여러 직원의 실시간 동기화를 제공할 수 없다.

## 현재 구현된 범위
- index.html 하나에 화면, CSS, JavaScript, 지도 경계, 애니메이션 아이콘이 들어 있다.
- 실행 코드에서 외부 API 호출이 없으며 외부 스크립트·스타일·폰트도 로드하지 않는다.
- index.html을 내려받아 PC에서 직접 열어 예시 화면을 실행할 수 있다.
- 지역 검색, 정렬, 지도 선택·미리보기·이동·휠 확대/축소, 제주도 별도 표시 등은 브라우저에서 처리한다.
- Content Security Policy로 자원과 통신 대상을 자체 출처로 제한했다. 인라인 코드·스타일은 기존 단일 파일 화면을 위해 허용한다.
- 지도 출처 링크는 사용자가 클릭하는 참고 링크다. 지도 표시에 외부 연결은 필요하지 않다.
- 현재 데이터와 동작은 예시이며 새로고침 후 유지되는 업무 데이터 저장, 실제 인증·승인·정산은 구현되지 않았다.
- CSP는 인증·접근 권한을 대신하지 않는다.

## 실제 업무 시스템의 배치 구조
직원 PC의 브라우저 → 회사 자체 웹 서버 → 자체 업무 API → 회사 데이터베이스 및 파일 보관소.

| 구성 | 자체 운영 방식 |
| --- | --- |
| 직원 화면 | /staff/ 및 /staff/login, 같은 서버의 정적 파일 |
| 관리자 화면 | /admin/ 및 /admin/login, 별도 소스 폴더와 관리자 권한 검사 |
| 업무 API | /api/, 화면과 같은 출처에서 제공 |
| 데이터 저장 | 내부 PostgreSQL, 외부 관리형 데이터베이스 불사용 |
| 첨부 파일 | 웹 공개 폴더 밖의 서버 저장소, 권한 확인 후 제공 |
| 지역 지도 | 저장된 경계 파일과 자체 SVG 렌더러 사용 |
| 이미지·텍스트 인식 | 서버에 설치한 로컬 OCR 엔진과 한국어 모델, 관리자 검토 후 반영 |
| 엑셀 입출력 | 서버에 설치·버전 고정한 로컬 라이브러리 |
| 급여·그레이드 | 서버에서 규칙 버전과 적용 기간을 기록하며 계산 |
| 명세서 출력 | 자체 HTML 인쇄 화면 또는 서버에 설치한 PDF 엔진 |
| 알림·갱신 | 같은 서버 API의 설정 가능한 주기 조회, 기본 1분 |
| 백업 | 회사가 지정한 별도 저장장치로 백업, 복구 절차 점검 |

이 표는 앞으로 구현할 운영 설계이며 현재 기능 구현 완료를 뜻하지 않는다.

## 예정 소스 및 데이터 분리
- frontend/staff: 직원 화면
- frontend/admin: 관리자 화면
- frontend/shared: 공통 스타일·컴포넌트
- assets/maps: 지도 데이터 및 출처·라이선스
- assets/icons, assets/fonts: 직접 제공하는 자원
- backend/auth: 계정·세션·권한
- backend/receptions, attendance, payroll, regions: 업무별 모듈
- backend/imports: 이미지·텍스트·엑셀 처리와 검토
- backend/audit: 승인·수정·정산 이력
- migrations: 데이터베이스 변경 이력
- tests: 급여 계산·중복·수량·권한 등 업무 규칙 검증
- 운영 데이터, 첨부, 백업, 비밀 설정은 위 공개 저장소 및 웹 루트와 분리한다.

현재 index.html은 미리보기 원본으로 유지하며 위 디렉터리가 구현되어 있다고 가정하지 않는다.

## 데이터 처리 기준
- 직원 화면에서 버튼을 숨기는 것과 별개로 API가 매 요청마다 권한을 검사한다.
- 관리자와 직원 로그인 주소를 분리하고, 퇴사 계정 차단 및 동시 로그인 제한을 서버에서 처리한다.
- 접수 승인·수량 차감·A/S 변경은 데이터베이스 트랜잭션으로 처리해 중복 차감을 방지한다.
- 급여와 그레이드는 서버에서 확정하며 직원 PC의 시각·화면 값으로 확정하지 않는다.
- 이미지 인식 결과는 바로 운영 정책에 적용하지 않고 원본과 대조 후 관리자 확정으로 반영한다.
- 신한 등 접수처의 표시 여부, 사용 여부, 지역·아이템·일 배정·잔여 수량은 관리자 설정 테이블로 관리한다.
- 현재 미리보기의 regionCarrierSettings 및 regions 상수는 이 설정을 대신하는 예시이며 관리자 저장 기능은 아직 없다.
- 인터넷 단절 시 미승인·미저장 내용을 성공 처리한 것처럼 표시하지 않는다.
- 주민·고객 정보 마스킹, 직원 다운로드 제한, 관리자 조회 및 변경 기록을 서버 권한에 맞춰 적용한다.

## 의존성 관리
- 오픈소스 패키지 사용과 외부 서비스 의존은 구분한다. 필요한 패키지는 라이선스를 확인하고 회사 서버에 설치·보관한다.
- 패키지·OCR 모델·설치 파일은 도입 시 내려받아 버전을 고정하고 오프라인 설치본과 함께 관리한다.
- 운영 중 자동 CDN 로딩, 원격 모델 호출, 외부 분석·광고 스크립트를 넣지 않는다.
- 지도는 현재 2018년 통계청 경계 자료다. 최신 경계 자료로 교체해도 자체 파일로 보관하며 출처를 유지한다.
- 프로그램 배포와 실제 고객 데이터 백업은 분리한다.

## 확인 항목
1. 외부 인터넷을 차단한 환경에서 화면·지도·문서 출력이 동작하는지 확인한다.
2. 요청 로그에서 허용한 내부 서버 외의 자동 요청이 없는지 확인한다.
3. 동시 승인, 중복 접수, 수량 복구, 정책 변경 기간, 퇴사자 정산을 검증한다.
4. 백업에서 복구한 데이터로 로그인과 업무 조회가 가능한지 확인한다.
5. 실제 업무 서버 공개 전 인증·권한·개인정보·정산 규칙을 검증한다.
